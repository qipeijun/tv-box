## 产品规则

- 使用 Node 后端统一处理站点请求、分类/搜索、详情与选集、播放地址解析、必要请求头和同源媒体转发；前端负责选择与播放。
- 尽可能复用有来源依据的同站点适配。不能因为显示名相同就绑定到其他 CMS 站点，也不能把执行任意 Android 插件作为新增来源的默认前提。
- 受账号或平台条件限制的资源显示真实条件；登录由用户本人完成，共享范围沿用家庭后端的已确认决定。不能把无法解析伪装为无影片。
- 支持状态逐源记录：待核对（尚无原始配置/契约）、开发中（接口或代码接入未验收）、接口通过（实际接口链路有证据）、播放通过（真实浏览器解码与控制有证据）、受阻（具体依赖/上游失败已定位）。接口通过不等于播放通过。

1. 光影、奶酪、热播的 Node 原生观看闭环已完成，含真实播放、切集、拖动和刷新续播；见 [验收记录](../development/node-source-compatibility-2026-10-30.md)。

3. 按实际协议分组接入截图来源；遇到相同接口能力再提取公共模块。每个源保留独立来源身份与验证证据。
4. 网盘源分别验证目录/搜索、分享解析、本人登录与真实播放；不把某个平台成功扩大为所有网盘可用。

首阶段三个站点只是现有执行目标，不替代这里新增的兼容范围。当前 Node 接入详情见 .scratch/backend-compatibility/map.md。

## 技术分组与执行次序

1. 普通在线影视：糯米、文采、立播、原创、苹果、白白、小熊。优先沿用可核实的 Node/JS 同站点规则；站点接口、HTML 抓取、签名和媒体解密各自落在后端。公开历史配置中的失效入口保留具体失败证据，不通过重命名别的 CMS 充数。
2. 预告片和直播：叨观荐影、一直播。分别按预告片、平台直播协议接入；直播窗口、仅原生播放器可用的格式和网页可解码格式分别表达。
3. 网盘检索及资源目录：玩偶哥哥、抠抠、优汐。检索、分享解析与登录播放分阶段验证；后端统一保存家庭授权，扫码仍由用户本人操作。

[drpy-node](https://github.com/Hululu007/drpy-node) 提供异步 Node 源引擎，已纳入可复用参考；没有为接入它新增常驻服务。当前先复用已核实的必要模块，避免将完整上游管理后台、插件进程和多引擎依赖全部带入现有应用。
