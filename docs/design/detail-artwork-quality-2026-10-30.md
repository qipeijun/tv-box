# 详情图片清晰度与构图

用户确认采用“清晰横图才铺满，否则切换完整海报构图”，手机与 PC 继续独立设计。

## 图片选择

- 只比较片库海报与已确认同片资料中的海报，不改写图片 URL 猜测高清版本，也不采用其他影片的图片。
- 解码得到实际宽高后选择像素更充足的海报；同尺寸保留片库原图。失败的图片不参与选择。
- PC 通栏仅使用资料中的横图，禁止将竖海报裁成横幅。按 cover 的实际缩放比例及 devicePixelRatio 判断，宽度与高度都必须够用。
- 判断使用详情容器宽度与当前主视觉高度。窗口尺寸、缩放或显示器像素密度变化后重新判断。
- 素材尚未完成解码或横图不够清晰时，PC 使用浅色背景、完整海报和信息区；缺图时收紧为文字首屏。
- 手机按自身封面尺寸及屏幕密度判断；像素不足时改为完整小幅海报。
- 完整前景海报也限制物理像素放大，不加模糊滤镜、锐化或 AI 细节补造。用户后续明确允许背景使用高斯模糊，见下方实施记录。

这里保证的是不因布局放大而进一步损失清晰度，无法识别或修复源图片本身的压缩、失焦和预先放大。

## 后续设计评审：大海报与信息组织（已实施，待浏览器验收）

用户基于《失控撞劫》PC 详情截图确认以下调整。本节记录目标设计，不代表下方历史验证已覆盖这些调整。

- 大海报承担首屏主视觉。有足够清晰且已确认同片的横版剧照时，以大幅横图构图，底部渐变衔接正文，片名和播放操作位于画面下沿。
- 只有竖版海报时，采用“大竖海报＋右侧影片信息”的独立构图，不把竖图拉伸或裁成横幅。海报仍遵守实际像素约束；素材不足不能通过放大低清图片来满足“大”的要求。
- 片名、年份／地区、简介组成连续信息组，播放、收藏与换站找片组成操作组；限制简介阅读宽度，收紧首屏内容范围，减少横向割裂。
- 仅有一个播放条目和一条线路时，收起整个选集区并隐藏“选集与线路”入口；存在实际选择时再展示对应选择能力。
- 原始线路标识移入线路选择，不作为详情正文信息。主播放按钮默认使用“立即播放”，存在可续播记录时使用“继续播放”；不把资源条目名“高清”当作已核实的画质承诺。
- 验收需覆盖清晰横图、仅竖海报、低清／缺图、单条目单线路以及多条目／多线路。检查主视觉、信息连续性、简介行宽、入口是否重复，以及续播按钮与实际记录是否一致。

### 实施与用户追加要求

用户授权实施，并追加“像素不足，用高斯模糊代替”。该指示替代此前背景禁止模糊的限制：

- PC 有足够清晰的横图时保留清晰通栏；横图像素不足时将其用作模糊背景，没有横图时使用已解码的同片海报作为模糊背景。
- 模糊层使用 32px 高斯模糊、边缘扩展和浅色渐变；前景独立展示完整海报，最大布局尺寸为 360×540，继续按原图像素和屏幕密度限制放大。
- 无可用图片时保留紧凑文字首屏，不制造图片占位。
- PC 片名、元信息和简介连续排列，操作集中在简介之后，正文与首屏共用阅读边界。
- 单条目单线路隐藏重复选集区；跨站确认或没有唯一选中条目时仍保留显式选择，防止隐藏必须操作的入口。
- 两端共用的播放按钮使用“立即播放”／“继续播放＋真实时间”，已选择条目时移除正文原始线路标识，多线路仍可在选择区查看。
- 手机与 PC 独立构图的约束继续有效；本轮海报与排版调整聚焦 PC。

验证：类型检查通过，现有 92 项测试通过；9 类场景的组件静态渲染检查通过，覆盖单条目、多条目、多线路、强制确认、续播、无播放入口，以及清晰横图／模糊背景／缺图。静态渲染不证明实际图片加载、CSS 视觉效果或点击行为。未启动开发服务，未构建、发布或进行本轮真实浏览器验证。

## 历史验证（本轮调整前）

单元测试覆盖普通屏／高密度屏、宽窗口、图片高度不足、竖图禁止作为横幅、未知容器尺寸及手机素材判断。

浏览器用隔离 API 和真实 TVmaze 图片检查展示，再用明确的 200×300 测试图片检查低清回退。验收脚本：scripts/verify-viewing-layouts.mjs。

实测结果：类型检查通过、现有 92 项测试通过。隔离 Chrome 验证普通 PC、高密度 PC、2560px 宽窗、3× 手机以及 200×300 低清素材回退通过；原有切集、全屏与返回检查通过。截图见 docs/development/screenshots/separate-viewing-layouts/poster-fallback-retina.png 与 poster-fallback-wide.png。未构建或发布。
