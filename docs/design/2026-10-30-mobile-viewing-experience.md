# 详情与手机播放体验讨论

## 已确认

- 改进范围包含详情加载、详情设计和播放页交互。
- 优先检查手机操作可靠性，再统一加载与视觉设计。
- 用户已授权浏览器验证及手机尺寸模拟。
- 手机竖屏采用上方视频、下方选集；横屏或主动全屏进入沉浸观看。
- 详情使用独立页面，明确拒绝弹框方案，需要精细化设计。
- 返回问题指 Web 播放页左上角应用内返回按钮经常难以点中。

## 当前证据

- 在已有本机服务上，以 390 × 844、支持触摸的浏览器模拟环境检查。
- 从首页打开详情，先出现整页骨架；列表中已有的片名与海报未用于加载首屏。
- 从详情进入播放，点击返回按钮中心，能够回到同一影片详情。
- 返回按钮中心横向多个采样点均命中按钮，尚无证据表明按钮整体被遮挡。
- 当前媒体尚未证明正常播放；未验证播放中自动隐藏控件、真实手机全屏及系统返回行为。

## 已实现与验证

- 详情采用海报渐变衔接深色背景的独立页面；手机与桌面分别构图。
- 从当前站点列表进入时，已有片名和海报在详情请求期间保留；预览按来源上下文与影片编号隔离。
- 手机竖屏恢复上方视频、下方选集；点击播放器选集入口滚动到页内选集。全屏与桌面保留选集面板。
- 手机播放导航采用单箭头、片名与集号；返回区域为 48 × 48 CSS px 矩形，保留按下反馈。
- 播放器模块加载期间也提供返回入口。
- 类型检查通过；现有 71 项测试通过。
- 独立 Chrome 手机触摸模拟（390 × 844）：返回区域四角与中心命中通过，左上边缘真实 tap 回到相同影片详情；页内选集可见。
- 延迟详情请求验证：已知片名和海报保持显示。
- 桌面 1440 × 1000 检查无横向溢出，并核对手机与桌面截图。
