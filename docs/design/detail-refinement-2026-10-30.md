# 详情页精致度对齐访谈

## 已确认要求

- 用户提供的移动端影片详情截图作为本轮详情页的最低视觉品质参考。
- 本轮使用 grill-with-docs 进行设计取舍访谈，确认方案后再实施。
- 手机端采用大幅海报、底部渐变衔接、悬浮工具与明确的标题/播放层级。
- 大屏端参照相同视觉特性重新构图，不照搬或放大手机长屏布局。
- 用户允许考虑外部平台评分获取；尚未选定平台、接入方式或凭据。
- 用户追加播放页与选集体验优化要求，本轮范围扩展为详情、播放与选集的连续观看路径；具体问题与方案仍在访谈中。
- 用户明确允许扩展外部平台能力以丰富详情页，不再限于评分；具体平台与字段范围仍为方案建议。
- 用户要求尽量选择爬虫抓取方式；“不免费的来”本轮暂按不付费优先理解，尚待纠正或后续确认，不视为已选定供应方。

## 播放与选集现状

- 手机竖屏与桌面均使用整屏黑色视频画布。
- 选集为居中弹框，弹框与集数区存在两层滚动；进入选集前会退出原生全屏，选完没有恢复全屏的处理。
- 每 30 集分组，线路和分组使用下拉框；当前集所在分组可定位，但当前集本身未自动滚动到可见位置。
- 播放选集面板切线仅改变待选列表，与详情页的同名集匹配行为不一致；打开面板时视频继续播放。
- 事实来源：src/components/video-player.tsx、src/components/episode-picker.tsx、src/App.tsx、src/styles.css。

## 建议范围（待确认）

- 第一阶段外部资料增强：优先评估 TMDB 的高清图片、来源明确的评分、上映信息、简介与演职员资料，先验证同片匹配和数据覆盖。
- 播放入口、线路与集数继续依据当前播放站点，外部资料不冒充播放可用性；剧集资料不可未经核对直接映射为站点集数。
- 预告片、演员独立页等新观看路径暂不作为第一阶段建议范围。

## 当前代码事实

- 当前手机详情为小海报与标题并列，桌面为海报与文字两栏。
- CMS 详情有单个海报地址，未记录图片尺寸或高清版本；没有横幅、演员头像、评分、精确上映日期或影片时长。
- 已有本地观看进度，详情按钮目前仅显示继续观看的集名，尚未展示时间点。
- 事实来源：src/components/film-details.tsx、src/styles.css、server/sources.js、src/lib/api.ts、src/lib/watch-history.ts。

### 免费与公开抓取核查

- 本机单次读取豆瓣电影 robots.txt 成功；其中排除了 /subject_search、/search 与 /j/ 等路径。robots 内容不等同于数据使用授权。
- 豆瓣电影样本 /subject/1292052/ 经普通 HTTP 请求跳转 sec.douban.com 安全检查页；最终 HTTP 200 不是影片详情抓取成功，未绕过检查。
- IMDb 官方提供个人与非商业用途数据集，包含评分和投票数；文档说明每日更新。本机对 title.ratings.tsv.gz 的 HEAD 请求返回 200，尚未下载、解析或验证具体影片匹配。
- IMDb 数据集可用于评分候选，但不提供本轮需要的高清图片与演员头像，不能单独解决详情视觉素材。
- 来源：[豆瓣 robots](https://movie.douban.com/robots.txt)、[IMDb 数据集说明](https://developer.imdb.com/non-commercial-datasets/)。

### 深入验证结果与建议调整

- MetaShark 的搜索、详情、演职员分别请求豆瓣页面或搜索建议入口；其本身不携带可独立使用的影视资料库。源码中的 HTML 解析不能解决上游访问被拦的问题。
- 新增豆瓣剧集样本 /subject/25754848/ 亦跳转安全检查页，未得到详情或评分；结合前一电影样本，不建议当前将匿名豆瓣抓取作为必需依赖。
- 发现免费、无需密钥的 TVmaze 公共 API。它是外部公共数据服务，不等同于已发现的开源爬虫组件。
- 实测英文名 Breaking Bad 返回目标剧集及相似候选，目标具有评分、海报、11 名带头像演员；中文查询“琅琊榜”返回 Nirvana in Fire（2015），具有 TVmaze 评分、1370×1920 海报和 1920×1080 背景图，但演员结果仅 1 名，说明资料并非完整。
- “琅琊榜”海报、背景图与演员头像三个图片 URL 的 HEAD 请求均返回 200 / image/jpeg；这是 HTTP 与接口声明尺寸核验，未进行浏览器显示或画面质量验收。
- TVmaze API 按 CC BY-SA 提供，使用须署名并满足相同方式共享要求；官网允许图片 CDN 直连并建议缓存。该服务主要面向剧集，电影详情与覆盖率问题仍未解决。
- 评分必须标注实际来源，TVmaze 评分不可标为豆瓣或 IMDb。匹配须核对身份、年份和作品类型，不能直接选择模糊搜索第一项。
- 建议调整为：开源项目用于参考解析与匹配；剧集增强可优先评估已实测 TVmaze；电影与完整中文资料继续评估免费服务，不以豆瓣抓取成功为已达成前提。不因外部资料暂缺阻断详情展示和播放。
- 本轮只做事实验证和方案记录，没有接入业务代码、安装依赖、构建或浏览器验证。

请求证据：[metadata-probe-2026-10-30.json](../development/metadata-probe-2026-10-30.json)。官方说明：[TVmaze API](https://www.tvmaze.com/api)。

### 电影资料补充验证

- Cinemeta 为 Stremio 官方影视目录插件，官方 SDK 文档提供请求其资料与名称解析的方法。本机匿名请求可用，无需提交密钥或付费。它是公共远端服务；未确认其服务端源码或数据再分发许可，不将 SDK 的 MIT 许可等同于资料许可。
- 两部电影详情样本成功：tt0111161《肖申克的救赎》、tt0106332《霸王别姬》，均返回 imdbRating、runtime、released、director、cast、poster、background 等字段。评分是 Cinemeta 返回的 IMDb 标识评分，未与 IMDb 当前官网独立交叉核对。
- 中文搜索均包含正确影片，但也含同名版本和无关结果；不能直接把首项当作已确认身份，跨语言片名与年份匹配仍需可靠证据或用户确认。
- 两部影片的海报与背景图四个 URL 的 HEAD 请求均返回 200 / image/jpeg，尚未核验图片像素尺寸和浏览器画质；不能称为高清验收通过。
- 两部详情样本的 cast 为姓名字符串，不含头像，不承诺电影演职员头像已解决。样本标题和简介以英文为主，建议保留 CMS 的中文内容。
- Cinemagoer 当前 README 表明因 IMDb 网站 WAF，其范围已转为官方可下载数据集；不能再把旧版网页抓取示例作为当前可用证据。
- 官方来源：[Cinemeta manifest](https://v3-cinemeta.strem.io/manifest.json)、[Stremio SDK 使用说明](https://stremio.github.io/stremio-addon-sdk/advanced.html)、[开源 MIT SDK](https://github.com/Stremio/stremio-addon-sdk)、[Cinemagoer 现状](https://github.com/cinemagoer/cinemagoer)。

## 收敛后的方案（用户已确认，2026-10-30 开始实现）

1. 资料路线：优先验证接入 Cinemeta 电影资料与 TVmaze 剧集资料，不引入付费依赖；接入前补齐远端服务使用条件核对。豆瓣不作为详情显示的必需依赖。
2. 资料身份：播放站点决定可播放集数和线路；资料服务仅增强展示。通过外部 ID 或可靠匹配确认影片身份后才展示评分和图片，有歧义时保留当前源内容，并允许在次级入口确认资料匹配。评分区明确标明平台与获取来源。
3. 详情构图：手机采用沉浸大海报与底部渐变；大屏优先使用清晰背景图配合标题与主播放动作，无横图时保留完整竖海报重新构图。保留中文简介；资料缺失不填假值或强行放大低清图片。
4. 信息层级：主播放按钮在简介前；显示真实可用的元信息及续播时间。简介、选集和演职员依次展开，人物有真实头像时显示头像，无头像时保留文字。
5. 播放布局：手机竖屏为上方视频、下方当前集与可操作选集；横屏或全屏采用沉浸画面。桌面选集在侧边展开，使用包含视频与面板的全屏容器；原生视频全屏无法覆盖 DOM 面板的平台明确保留实际能力边界。
6. 选集与切线：紧凑网格、可见集数分组、当前集自动进入可视区域，避免双层滚动。打开面板时继续播放；选集后收起面板并保留原观看模式。换线路尝试唯一对应集，不能唯一确认则要求选集；定位旧进度失败时明确反馈。
7. 验收：先完成相关行为测试与类型检查；375px 手机及桌面需在获得浏览器验证授权后分别实测。重点覆盖缺图/缺资料、匹配歧义、长剧集、当前集定位、全屏选集、切线失败及返回续播；不以 HTTP 成功代替画质和播放验收。

实现与验证进度见 [详情与观看优化验证记录](../development/detail-watch-2026-10-30.md)。
