# 详情页体验完善

## 目标与视觉方向

面向从片库找片并开始观看的用户，详情页的首要任务是说明作品并明确下一步播放目标。保留浅色正文、通栏画面和独立手机/PC 布局。

沿用颜色：正文底色 #fafafa、标题 #151619、说明 #62656a、选集表面 #eeeff1、选中表面 #dce3e7、焦点 #3b657b。标题使用现有 ui-rounded/PingFang SC，正文沿用系统字体，集数采用等宽数字。PC 标题 28–38px，正文 14px，辅助说明 12–13px。

将“播放目标”和选集工具栏作为页面识别点，其他元素保持克制。PC 信息与选集共用 1120px 边界；手机长集名独立使用宽列，不强行沿用数字集号的小格。

```text
PC：通栏背景（可独立补图）
    [固定海报槽] 片名 / 信息 / 简介 / 播放目标
    选集                         状态 / 定位 / 排序
    上一组  [范围] 下一组
    集名网格

手机：固定封面区（无图时移除）
      片名 / 信息 / 全宽播放目标 / 次级操作
      简介 / 选集工具栏 / 集名网格
```

自查后放弃“补充高清图后升级为更大首屏”的方案：补图只更新已有画面区域，不切换容器结构。手机有图时封面区固定 320px，PC 前景海报槽固定 220×300px；保留实际像素约束，不把低清图片放大至槽位尺寸。原始片库缺图时使用文字优先构图，后续补图可更新背景但不插入新的海报列。

## 行为

- 默认第一集标为待播放；续播记录标为上次观看；播放面板标为正在播放。主按钮明确集名，续播附真实时间。
- 详情与播放选集共享本次会话的排序偏好；切换排序从首组开始，独立提供定位。展示排序不改变自动连播。
- 日期及其他长集名使用宽列并换行；当前图标独立占位。
- 简介仅在实际超过折叠行数时显示展开，宽度变化时重新测量。缺失简介使用次级说明。
- 详情局部采用浅色原生控件主题；键盘焦点沿用全局可见样式，排序与定位的点击高度至少 44px。

## 验证与限制

- `npm run typecheck`。
- `npm test`：109 项通过，覆盖现有播放、切线、续播及分组规则。
- `node scripts/verify-detail.mjs`：无浏览器的组件静态渲染检查，覆盖长集名、倒序首组、正在播放定位、单集、补图前后结构、无图、简介及续播文案。
- 用户明确选择仅做源码与自动化测试。本轮不启动浏览器；简介实际溢出测量、触屏手感、画面比例与真实布局位移未实测。静态渲染检查不代替视觉验收。
