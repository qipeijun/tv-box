# 播放与详情加载优化

面向直接观看影视的用户，首要任务是让画面、返回和播放操作可靠可达。

## 设计

延续影视页面的深海蓝：画布黑 #000000、返回底色 #101E2B、悬停蓝 #253C50、骨架蓝 #243843、正文白 #F2F6FA、焦点蓝 #A7CEE6。片名延续项目现有系统字体与紧凑标题字距，正文沿用中文无衬线，时间使用等宽数字。不增加字体下载。

结构为「常驻返回 + 影片标题 / 完整画面 / 进度与控制」。唯一强调元素是常驻的胶囊返回入口，48px 点击高度与安全区间距让它即使在控件隐藏时也能找到。视频保持 contain，不通过裁切填满屏幕。手机竖屏使用整个视口，选集在底部面板展开。

详情骨架复用真实首屏的海报和信息布局；资料背景与海报质量变化不再切换首屏尺寸。原先的小块加载提示无法传达内容结构，改为完整骨架；不增加无关装饰或入场动画。

## 验收与边界

- 返回入口独立于控件显隐，点击区域不被顶部渐变或底部控件覆盖。
- 操作控件时不自动隐藏；移出播放器不立即隐藏。
- 拖动进度时预览时间，释放后定位；键盘仍直接调整进度。
- 手机选集打开同一选集面板，连播设置仍可访问。
- 标准 Fullscreen API 不可用时尝试视频原生 WebKit 全屏；不支持时给出说明。
- 类型检查和现有自动化测试验证代码；浏览器布局、触摸与 iOS 全屏需获得授权后验证。

## 浏览器回归结果

用户授权后，使用隔离的无头 Chrome 与本机 60 秒测试短片，检查 1440×900、390×844、320×740 三种视口。原有 Vite 返回缓存样式，另启临时 5192 端口加载最新源码验证；原有服务未修改。

三种视口均通过：加载骨架与详情显示、播放器占满视口、标题不与返回重叠、标准全屏进出、选集面板开关、控件隐藏后返回按钮的命中检测与真实点击。进度拖动期间不跳转，释放后分别定位至 36.3、36.4、36.1 秒，三秒内完成；无页面运行时异常。测试短片以 Blob 完整加载，排除测试 HTTP 服务没有有效可定位区间的干扰，不代表真实线路的缓冲性能。

浏览器检查修复两项问题：旧手机选择器覆盖标题左间距；原生 change 在释放后再次写回旧时间。进度预览改用 input 事件，释放时读取本次拖动位置引用。
