# 自动下一集与结束交互验证 · 2026-10-30

## 实现与边界

任务 08 已完成。默认连播，可在 PC 非模态选集侧栏或手机页内选集区关闭，使用 Radix Switch。偏好存于 `tvbox.playback.v1`，版本 1；损坏或未知版本暂时关闭并保留原数据，只有用户改变开关才重建。写入失败明确提示，不阻塞播放。

下一集只取当前线路原始数组中紧邻的一项，不解析集名数字、不排序、不跳过不可播放项，不跨线或循环。末集停止。结束画面提供手动下一集（有可播下一项时）、选集与重播；开启连播不会追溯触发已结束的一集。

结束回调校验来源、影片、当前集与实时播放路由；旧播放器和重复结束事件不能推动新选择。浏览器拒绝自动播放时保留下一集、显示点击播放，不重试循环。原生 HTMLVideoElement.play() 的 Promise 反馈启动结果，Video.js 继续负责媒体处理、事件和定位，避免快速切集时排队播放请求长期停留加载态。媒体尚无元信息时等待 loadedmetadata/canplay，活动播放中断会提示点击继续。每集开始立即保存实际观看记录，随后按原有节流保存进度。

## 复现短片

在构建后临时生成文件，再将脚本作为隔离上下文 initScript 注入。仅在 review 查询以 auto-next 开头、127.0.0.1 主机上生效；正常产品不导入脚本。可用 mode=deny-next、slow、corrupt 验证拒播、慢播放和损坏设置。结束后删除生成短片，不将其作为产品资源交付。

```sh
mkdir -p dist/__playback_check__
ffmpeg -hide_banner -loglevel error -f lavfi -i 'color=c=0x14202a:s=320x180:r=12:d=2' -an -c:v libx264 -pix_fmt yuv420p -movflags +faststart -y dist/__playback_check__/next.mp4
```

入口示例：`http://127.0.0.1:4781/?review=auto-next-check#watch=fixture&episode=0%3A0`。注入仅改变隔离页数据，需在正常页面验证真实来源；不能用测试接口响应证明订阅稳定。
