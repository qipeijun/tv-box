# 源兼容能力集成到一个后端服务

2026-10-30，用户明确不希望运行多个服务。本轮源兼容扩展保持一个后端部署单元、一个启动入口与对外端口；站点适配、脚本规则、网盘登录和媒体代理由该后端统一提供。撤回将独立常驻 Android 兼容服务作为优先方案的建议。

此决定约束部署方式，不决定后端语言。用户进一步要求充分研究 Java 等替代方案，因此不将保留 Node 视为已确认要求。用户没有要求一个操作系统进程；应用内部管理的执行任务与需要用户单独配置、启动、维护的服务应分别评估。

直接执行原工件、通过兼容层执行与重新适配同站点是不同技术路径；单服务方案须按真实站点验证，不能仅凭类名或片名用其他来源替换。若目标站点无法在该约束下接通，应记录缺口并提出有证据的取舍，不自行新增需要独立维护的服务。

2026-10-30 后续修订：用户指出 Java 路线偏离预期，要求使用 Node.js 实现饭太硬支持。当前采用 Node 原生同站点适配、按需解析与同源媒体转发，继续沿用一个服务和端口。旧 Java 原型留作失败证据，不进入生产启动链路。截图追加的 Spider 来源也纳入此方向，逐源核对真实配置与观看能力；尚无适配的站点仍明确显示原因。
